# MARSWALK — HUD 데이터 매핑 명세 (2026-11-15)

> **핵심: HUD는 새 데이터가 없다.** 패드(PAD)와 같은 grid·모델·정적 데이터를 그대로 읽어 **현장용 최소 화면**으로 표시할 뿐.
> 개발자용: "HUD 요소가 어느 데이터/모델을 읽나"를 못 박음. 데이터 작업(DA)은 없고, 전부 프론트(UI) 작업.

---

## 0. 원칙
- **HUD = PAD 데이터 재사용.** 같은 Zustand store를 구독, 최소 필드만 렌더.
- 기준: *"지금 안 보면 죽나?"* → 그것만 HUD. 나머지는 PAD.
- UI만 다름(크게·고대비·물리버튼). **데이터·모델은 동일.**

---

## 1. HUD 페이지별 데이터 매핑

| HUD 요소 | 읽는 데이터/모델 | 출처 | PAD와 |
|---|---|---|---|
| **H1 복귀 여유** | walk-back 반경 − 현재거리 | 소모품·복귀선 모델 | ✅ 동일 |
| **H1 산소** | o2 잔량 | 산소 모델(아폴로 PLSS) | ✅ 동일 |
| **H1 방위와 거리** | 현위치→목적지 벡터 | 위치+지도(기하) | ✅ 동일 |
| **H1 회피 큐** | grid `slope_deg>25` · `comm=shadow` | DEM 격자 | ✅ 동일 |
| **H1 버디 간격** | 2번째 대원 위치 − 내 위치 | 🆕 위치 입력 | 신규(데이터셋 아님) |
| **H2 작업 항목** | 미션 작업 리스트 | 🔶 입력 | — |
| **H2 잔여 체류 시간** | walk-back 여유 / 소모율 | 복귀선·소모품 | ✅ 동일 |
| **H2 지점 영상 대조** | Perseverance 실사 | spots(raw API) | ✅ 동일 |
| **H3 영상 마킹** | 카메라 프레임 + 위치 태그 | 🆕 기기(카메라) | 기능(데이터 아님) |
| **H3 음성 받아쓰기** | 마이크 → STT | 🆕 기기(마이크) | 기능 |

| **H4 경보 내용** | 안전 게이트 트리거(복귀선·피폭·산소) | 모델 로직 | ✅ 동일 |
| **H4 물리 버튼 매핑** | 선택지 → 하드웨어 키 | 🆕 기기(버튼) | UX |
| **H4 합의 분기** | 대원↔관제 확인 플로우 | 🔶 로직 | — |
| **H5 복귀 개시 안내** | point of no return 판정 | walk-back 모델 | ✅ 동일 |
| **H5 기지 방위** | 현위치→기지 벡터 | 위치+기지(기하) | ✅ 동일 |

---

## 2. HUD만의 신규 (데이터 아님)
| 항목 | 성격 | 필요한 것 |
|---|---|---|
| 버디 위치 | 위치 입력 | 2번째 대원 좌표 피드(실제 미션은 수트 텔레메트리) |
| 영상 마킹·음성 STT | 기기 기능 | 카메라·마이크 API |
| 물리 버튼 | 하드웨어 UX | 수트 입력 매핑 |

**셋 다 과학 데이터셋이 아니라 "기기/입력 연동"** → DA 영역 아님, 개발/하드웨어 영역.

---

## 3. 개발 메모
- HUD 화면들은 **PAD와 같은 store 구독**, 최소 필드만 큰 글씨·고대비로.
- 회피 큐·경보 = PAD의 안전 게이트 로직 그대로 재사용(중복 구현 금지).
- H3 기록 = 기기 API 연동(카메라/마이크) → 데이터는 위치·시각·상태를 store에서 자동 첨부.
- 물리 버튼 = 선택지를 키 이벤트에 매핑.

---

## 4. 데이터 핸드오프 관점 결론
- **HUD용 새 데이터·전처리 없음.** 데이터 zip 하나로 PAD·HUD 둘 다 커버.
- HUD는 **100% 프론트(UI) 작업** + 기기 연동(카메라/마이크/버튼).
- DA가 넘길 것: 이 매핑 1장 + 기존 데이터(grid·모델·정적 파일).
